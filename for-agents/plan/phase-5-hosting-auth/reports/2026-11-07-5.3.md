## Changed

- `frontend/src/shared/components/layout/Header.tsx` — `useQuery(['me'])`; when signed in, the name (hidden below `sm`) and a "Sign out"/"Гарах" link to `/api/auth/logout` with the existing 44 px target size.
- `frontend/src/shared/i18n.tsx` — `auth.signOut` mn + en.
- `frontend/tests/shared/utils/report-requests.test.ts` — 2 tests: only 401 triggers login; `fetchMe` 200/404/5xx.

## Review fixes (2026-11-08, `/tmp/rev-p5-hosting-report.md`)
- `withLogin`: a 401 on a GET redirects at most once per 60 s (sessionStorage `loginAt`; no storage → no auto-redirect); otherwise, and for any 401 on a POST, it emits `failed`/`expired` on `authProblems` instead. `fetchMe` clears `loginAt` once signed in.
- Header: on an auth problem, an alert with "session expired"/"sign-in did not complete" and a "Sign in" button; sign-out is now a POST form. Chat shows `auth.expired` on 401; support upload's `supportErrorText` takes `expired`. New mn+en strings `auth.signIn`, `auth.expired`, `auth.failed`.
- Tests (+4, adjusted 2): loop guard (second 401 within a minute → `failed`, after 61 s redirects again), no storage → no redirect, POST 401 → `expired` without redirect, `fetchMe` clears the guard, support 401 → expired text.
